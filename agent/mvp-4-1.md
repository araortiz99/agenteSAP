# MVP 4.1 — Structured Citations and Ticket Context

## Objective

MVP 4.1 makes the LLM response auditable by separating the natural-language
answer from structured provenance.

## Citation contract

Every citation emitted by the LLM must reference an evidence ID generated by
the deterministic traceability layer:

`EVD-XXXXXXXXXXXX`

The application validates every citation after generation.

If the model cites an unknown `EVD-*`, the consultation fails instead of
accepting an untraceable citation.

Structured citation fields:

- `citation_id`
- `evidence_id`
- `path`
- `source_id`
- `certainty`

The model cannot create or modify these fields.

## Ticket context

When the request contains a ticket identifier, the consultant retrieves:

1. the existing `tickets/<ticket_id>/` Markdown documents;
2. explicitly documented relationships for `TICKET/<ticket_id>`.

Ticket documents receive deterministic `TKT-*` reference IDs.

A missing ticket is not synthesized. The repository remains the source of truth.

## Response object

The consultation result exposes:

- natural-language `answer`;
- `citations`;
- `uncited_evidence_ids`;
- `ticket_context`;
- `ticket_relationships`;
- deterministic `traceability`;
- deterministic `reasoning`.

## Evidence rules

- `confirmed` remains `confirmed`;
- `partial` remains `partial`;
- `under_validation` remains `under_validation`;
- SAP Standard and internal evidence remain separate layers;
- ticket context is contextual evidence and does not automatically become
  authoritative SAP Standard;
- no relationship is inferred from co-occurrence.
